All skillsToàn bộ skill

68 skills

Every hs:* skill is prose guidance — a structured prompt that tells Claude Code what to do. The real blocking happens in hooks and scripts. Skills are packaged in a default-off catalog: fresh install ships a core floor (13 spine skills + hs:find-skills + hs:cleanup), the rest you enable via hs-cli skills --on. A skill that is off cannot be run — read it from its stash, or turn it on.Mỗi skill hs:* là hướng dẫn prose — một prompt có cấu trúc cho Claude Code biết cần làm gì. Việc chặn thực sự xảy ra trong hook và script. Skill được đóng gói ở catalog default-off: cài mới ship floor lõi (13 spine skill + hs:find-skills + hs:cleanup), còn lại bạn bật qua hs-cli skills --on. Skill đang tắt thì KHÔNG chạy được — đọc từ kho, hoặc bật lên.

💡
A skill is only as strong as the hook that enforces it. Browse the catalog to find the right skill — then see the rig to understand what actually blocks bad output from shipping.Skill chỉ mạnh bằng hook thực thi nó. Duyệt catalog để tìm skill phù hợp — rồi xem the rig để hiểu cái gì thực sự chặn đầu ra xấu khỏi ship.

Invoke any skill with /hs:<name>. The badge on each card is its enforcement tier: workflow has gates & artifacts (can block the pipeline) · knowledge is advisory (generates output, never blocks) · gate writes a hard verdict the pipeline reads. Most skills are knowledge or workflow; only a few write a hard gate verdict. Gọi skill bằng /hs:<tên>. Badge trên mỗi thẻ là hạng cưỡng chế: workflow có gate & artifact (chặn pipeline được) · knowledge là tư vấn (tạo output, không chặn) · gate ghi verdict cứng pipeline đọc. Phần lớn skill là knowledge hoặc workflow; chỉ một số ít ghi verdict gate cứng.

hs:plan workflow

Create a verified implementation plan — research, constraint-scan, phase design, red-team, validate — with an optional coverage-grid planning mode for systematic axis coverage. Produces a human-approvable plan file.Tạo kế hoạch triển khai có kiểm tra — research, constraint-scan, thiết kế phase, red-team, validate — có chế độ lập-kế-hoạch coverage-grid tùy chọn để phủ trục có hệ thống. Tạo file plan để người duyệt.

hs:cook workflow

Execute an approved plan phase by phase, TDD red→green — including filling a coverage-grid plan's cells under an anti-confab contract. Each phase emits a verification artifact and a trace event.Thực thi plan đã duyệt từng phase, TDD đỏ→xanh — kể cả điền ô của plan coverage-grid theo hợp đồng chống-bịa. Mỗi phase emit artifact verification và sự kiện trace.

hs:test workflow

Run and validate tests — unit / integration profiles — and produce a QA report with a machine-readable verdict in verification.json.Chạy và validate test — profile unit/integration — tạo QA report với verdict đọc được bởi máy trong verification.json.

hs:ship workflow

Gated ship pipeline: code-review → verification → human approval → push/pr. Each gate is a hard stop.Pipeline ship có gate: review code → verification → người duyệt → push/pr. Mỗi gate là điểm dừng cứng.

Are skills the thing that blocks bad output?Skill có phải thứ chặn đầu ra xấu?
No. A skill is prose — a structured prompt. Blocking happens in hooks and scripts (gate_stage, write_guard, the pre-push backstop). A skill is only as strong as the hook that enforces it.Không. Skill là prose — một prompt có cấu trúc. Việc chặn nằm ở hook và script (gate_stage, write_guard, backstop pre-push). Skill chỉ mạnh bằng hook thực thi nó.
How do I invoke a skill?Gọi một skill thế nào?
Type /hs:<name> in Claude Code — e.g. /hs:plan. Skills can be chained (orchestrators spawn subagents) or invoked standalone.Gõ /hs:<tên> trong Claude Code — ví dụ /hs:plan. Skill có thể nối (orchestrator sinh subagent) hoặc dùng độc lập.
I don't know which skill fits — what now?Không biết skill nào hợp — làm sao?

Is the count exact?Số lượng có chính xác không?
Yes — 129 skills at this build (a skill is a dir with its own SKILL.md; 3 more dirs — _docslib, _shared, common — are shared libraries, not invocable skills). New skills land over time; harness/plugins/hs/ is the live source of truth.Có — 129 skill ở bản build này (một skill là một thư mục có SKILL.md riêng; 3 thư mục khác — _docslib, _shared, common — là thư viện dùng chung, không phải skill gọi được).
