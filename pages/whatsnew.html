What's newCó gì mới

v6.2.0 · 2026-08-25

One porting job, and the interesting part is that it stayed honest under eight different runtimes. runtime-targets.yaml + a projector now declare, one measured fact at a time, what each of eight external coding-agent runtimes can actually carry — event names, tool vocabulary, hook-file shape — and turn that table into a real install instead of a copy that looks installed but fires nothing. Losing a compliance gate's matcher is a hard error, never a silent drop. Everything else in this cut is smaller doors built the same way: a real bridge instead of a blanket refusal, a narrow per-project override instead of an edit to the shared file, and two independent layers so a flag a skill promises never depends on one paragraph surviving intact.Một đợt port, và phần đáng nói là nó giữ được trung thực dưới tám runtime khác nhau. runtime-targets.yaml + một projector giờ khai báo, từng sự thật đã đo một, tám runtime coding-agent ngoài Claude Code thực sự mang được gì — tên event, từ vựng tool, hình dạng file hook — rồi đúc bảng đó thành một install THẬT thay vì một bản copy trông như đã cài mà không bắn gì cả. Mất một matcher của gate compliance là lỗi cứng, không bao giờ rơi rụng âm thầm. Mọi thứ còn lại trong bản này là những cánh cửa nhỏ hơn dựng theo cùng nguyên tắc: một cầu-nối thật thay vì từ-chối chung, một override per-project hẹp thay vì sửa file dùng chung, và hai lớp độc lập để một cờ mà skill đã hứa không phụ thuộc vào việc một đoạn văn còn sống sót.

🌐 An eight-runtime port, each claim traceable to a measurement🌐 Port tám runtime, mỗi lời khai truy được về một phép đo

harness/data/runtime-targets.yaml + target_projection.py declare event casing, tool vocabulary, hook-file shape, skill-name constraints, and model-tier maps for eight external coding-agent runtimes. hs-cli emit --target T --out DIR negotiates that table against hook-dispatch.yaml into a runnable install — hooks file, degradation ledger, operator notes. install.py --runtime <csv> installs per-project; --runtime-home is a deliberately separate door for the two runtimes that live in the user's home, because a flag whose blast radius depends on a table nobody read is a flag that surprises someone. Every install writes a reversible ownership ledger a user-edited file survives.harness/data/runtime-targets.yaml + target_projection.py khai báo cách viết hoa event, từ vựng tool, hình dạng file hook, ràng buộc tên skill, và model-tier map cho tám runtime coding-agent ngoài Claude Code. hs-cli emit --target T --out DIR đúc bảng đó cộng hook-dispatch.yaml thành một install chạy được — file hook, sổ suy-giảm, ghi chú vận hành. install.py --runtime <csv> cài per-project; --runtime-home là cửa RIÊNG cố ý cho hai runtime sống ở home máy, vì một cờ mà bán kính ảnh hưởng phụ thuộc vào một bảng chẳng ai đọc là một cờ khiến ai đó bất ngờ. Mọi lần cài ghi sổ sở-hữu đảo-ngược-được mà một file người dùng đã sửa vẫn sống sót.

🌉 pi gets a real hook bridge, not a blanket refusal🌉 pi nhận cầu-nối hook thật, không phải từ-chối chung

pi takes hooks only from a generated TypeScript extension, never a JSON config — previously modeled as a flat refusal covering every gate. The generated bridge shells out to the same Python dispatcher every other target already calls. A live probe against a real pi install then caught the first design cold: pi.exec's ExecOptions hardcodes stdio with no stdin passthrough, so the payload the bridge handed it never arrived — every routed tool call would have gone unguarded. The bridge now spawns the dispatcher directly, the same pattern pi's own upstream hooks extension uses.pi chỉ nhận hook qua một extension TypeScript sinh ra, không bao giờ qua JSON config — trước đây mô hình hoá bằng một từ-chối phẳng phủ mọi gate. Cầu-nối sinh ra shell thẳng tới cùng dispatcher Python mà mọi target khác đã gọi. Một lượt probe SỐNG trên bản cài pi thật sau đó bắt được thiết kế đầu tiên ngay lập tức: ExecOptions của pi.exec ghim cứng stdio không có đường stdin, nên payload cầu-nối đưa vào không bao giờ tới nơi — mọi tool call định tuyến qua đó lẽ ra đã chạy KHÔNG canh gác. Cầu-nối giờ spawn dispatcher trực tiếp, đúng cách extension hook gốc của pi đang làm.

🎛️ Per-project hook on/off, narrowed on purpose🎛️ Bật/tắt hook per-project, thu hẹp có chủ đích

A shared-bin install serves one harness-hooks.yaml to every project — a project wanting one nudge on no longer edits the file every other project reads. data_root()/harness-hooks.yaml is a per-project overlay that MERGES over the shipped registry: an unmentioned hook keeps its shipped state. hs-cli hooks reports every hook's resolved posture and which layer decided it; --off/--on <csv> writes only the project overlay and refuses a name the guard-policy plane owns without --force. Stage/guard policy, output language, and voice stay bin-global, untouched.Một bản cài shared-bin phục vụ CÙNG một harness-hooks.yaml cho mọi project — project muốn bật một nudge không còn phải sửa file mà project khác cũng đọc. data_root()/harness-hooks.yaml là tầng phủ per-project GỘP lên sổ đã ship: hook không được nhắc tới giữ nguyên trạng thái đã ship. hs-cli hooks báo tư thế đã giải của mọi hook và tầng nào quyết; --off/--on <csv> chỉ ghi tầng project và từ chối tên mà mặt guard-policy sở hữu nếu thiếu --force. Stage/guard policy, ngôn ngữ output, và voice vẫn bin-global, không đụng.

🎭 --ultra/--debate reach 13 skills, two ways at once🎭 --ultra/--debate tới 13 skill, hai đường cùng lúc

The flags previously lived only inside hs:workflow-orchestrate's own script — nothing in the 13 downstream skills recognized them. Each now carries a Panel-mode order to call the panel, naming hs:escalation-consultant as the reader. A second, independent UserPromptSubmit hook regexes the raw prompt for a panel skill plus the flag and injects the routing directive whether or not the skill body still carries it — so the wiring survives a future edit that strips the paragraph. hs:cook stays deliberately excluded: it mutates code, not the read-only shape the panel is built for.Trước đây các cờ này chỉ sống trong chính script của hs:workflow-orchestrate — không skill nào trong 13 skill downstream nhận ra chúng. Mỗi skill giờ mang một đoạn lệnh Panel-mode gọi panel, nêu tên hs:escalation-consultant làm người đọc. Một hook UserPromptSubmit thứ hai, độc lập, regex prompt thô tìm skill-panel cộng cờ và tiêm chỉ dẫn định tuyến bất kể thân skill còn giữ đoạn đó hay không — nên việc nối dây sống sót qua một lần sửa sau này lỡ xoá mất đoạn văn. hs:cook vẫn cố ý bị loại: nó sửa code, không phải hình dạng chỉ-đọc mà panel được xây cho.

Also changed & fixedCòn đổi & sửa

ChangedĐã đổi

  • Stuck-streak auto-escalation now spawns hs:escalation-consultant for counsel on a repeated non-terminal state, and orchestration-protocol.md gains a fourth judgment trigger: a phase boundary whose actual outcome — not its mere completion — changed the downstream risk.Leo-thang tự động khi kẹt-lặp giờ spawn hs:escalation-consultant để xin ý kiến khi cùng trạng thái không-cuối lặp lại, và orchestration-protocol.md có thêm điều kiện leo-thang thứ tư: một mốc phase mà KẾT QUẢ THẬT của nó — không phải chỉ việc hoàn thành — đổi rủi ro của các bước sau.
  • --debate joins --ultra as one peer shape of a single panel (N independent producers, one separate reader), and --yagni lands as one scope-posture seam in hs-run, defaulting to full scope everywhere.--debate gia nhập --ultra thành một hình dạng ngang hàng của MỘT panel (N nhà sản xuất độc lập, một người đọc riêng), và --yagni vào như một seam scope-posture ở hs-run, mặc định giữ nguyên phạm vi ở mọi nơi.
  • 24 diagram types (light/dark/full) and a vendored chart bundle ship under harness/assets/, each with a VENDOR.yaml integrity record a gate recomputes — a template edited in place goes red instead of silently drifting from the upstream it still names.24 loại sơ đồ (light/dark/full) và bộ chart vendor hoá ship dưới harness/assets/, mỗi cái kèm bản ghi toàn vẹn VENDOR.yaml mà một gate tính lại — sửa trực tiếp một template thì đỏ thay vì trôi âm thầm khỏi bản gốc nó vẫn còn nêu tên.

FixedĐã sửa

  • Fifteen skills nothing pointed at, and eleven skills missing from every install component-group menu, both now reachable by meaning — not only by a user typing the exact name.Mười lăm skill không ai trỏ tới, và mười một skill vắng khỏi mọi menu nhóm cài đặt, giờ đều tới được bằng Ý NGHĨA — không chỉ bằng việc gõ đúng tên.
  • A renamed event read as an absent one: one runtime's own name for UserPromptSubmit was compared only after a first-letter lowercase, dropping the whole per-turn rule-routing lane for that runtime.Một event bị đổi tên đọc thành VẮNG MẶT: tên riêng của một runtime cho UserPromptSubmit chỉ được so sau khi hạ chữ cái đầu, làm rơi cả lane định-tuyến-rule-mỗi-lượt của runtime đó.
  • Hook files were written in one runtime's shape for every runtime — wrong grouping, wrong casing, wrong tool vocabulary, a decision-object dialect mismatch that made a deny silently pass. Every dimension now comes from the declared table.File hook từng được viết theo hình dạng của MỘT runtime cho mọi runtime — sai cách nhóm, sai viết hoa, sai từ vựng tool, lệch phương ngữ decision-object khiến một deny lọt qua âm thầm. Mọi chiều giờ lấy từ bảng đã khai.
  • An install onto a runtime's project-instructions file replaced it instead of splicing into it — measured on a real file, an install deleted three hand-written lines it had no business touching.Một lần cài lên file chỉ-dẫn-project của runtime đã THAY THẾ thay vì ghép vào — đo trên một file thật, lần cài đó xoá mất ba dòng viết tay mà nó không có quyền đụng vào.
